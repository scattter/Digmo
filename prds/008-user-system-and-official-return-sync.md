# 008 用户体系与官方涨幅同步修复 PRD

## 1. 背景
系统从单用户模式演进到可上线的多用户模式，需要在数据层做用户隔离并具备可迁移能力；同时交易日收盘后部分基金官方涨幅显示滞后，影响收益可信度。

## 2. 目标
1. 引入账号体系（`username + password + JWT`），所有业务数据按 `user_id` 隔离。
2. 提供可回放的数据导出/导入能力，支持上线后快速迁移。
3. 修复官方净值日期识别与收盘后刷新时效问题，保证官方涨幅发布后可快速显示。

## 3. 范围
### 3.1 后端 API
- `POST /v1/auth/login`
- `GET /v1/auth/me`
- 受保护接口：`/v1/portfolios*`、`/v1/funds/flat`

### 3.2 数据层
- `app_user`
- `user_portfolio`
- `user_fund_state`
- `user_portfolio_fund`

### 3.3 运维 CLI
- `user:create`
- `data:export --username <u>|--all --out <file>`
- `data:import --in <file> --mode upsert`

## 4. 关键方案
### 4.1 鉴权与用户
1. 使用 JWT Access Token（12h）作为 API 鉴权凭证。
2. 不开放自注册，首版用户由 CLI 创建。
3. 路由中间件统一从 Token 提取 `user_id`，客户端不再传用户标识。

### 4.2 用户数据隔离
1. 组合、持仓、基金状态数据全部落在 `user_id` 维度。
2. 同名组合允许在不同用户下并存。
3. 数据读写默认强制 `where user_id = currentUserId`。

### 4.3 迁移与可搬迁
1. 启动时执行幂等 migration（旧结构自动迁移到 user-scoped 结构）。
2. 历史单用户数据归属默认管理员。
3. 导出包为 JSON（含元信息、用户、组合、持仓、fund_state），导入按依赖顺序事务 upsert。

### 4.4 官方涨幅显示修复
1. 修复净值日期解析口径：`Data_netWorthTrend` 时间戳按上海时区生成交易日日期，避免 UTC 偏移导致“晚一天”。
2. 优化收盘后估值幂等策略：
   - 交易时段：保留 bucket 幂等。
   - 非交易时段：允许按缓存窗口重算，官方净值发布后可快速反映。

## 5. 验证
1. 认证与数据隔离测试通过（无 token/非法 token/跨用户访问均被拒绝）。
2. 迁移幂等验证通过（重复启动不重复迁移）。
3. 导出导入验证通过（计数与关键字段一致，重复导入 upsert 无脏重复）。
4. 新增官方涨幅回归测试，覆盖收盘后同 bucket 内官方净值更新可见。

## 6. 验收标准
1. 未登录无法访问受保护接口，登录后功能全链路可用。
2. 任意用户仅可访问自己的组合与持仓数据。
3. 通过 CLI 可完成账号创建、全量/按用户导出与导入。
4. 交易日收盘后，官方涨幅发布后系统在短时间内同步显示。
