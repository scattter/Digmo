# Digmo Web UI/UX 组件化重构 PRD（ui-ux-pro-max + shadcn-ui）

> 更新时间：2026-03-05（与当前前端实现保持一致）

## 背景

Digmo Web 已完成从单体页面到组件化结构的改造，但交互细节在连续迭代中发生了多次调整。为了避免设计与实现脱节，本 PRD 作为当前 Web 端 UI/UX 基线，统一记录已锁定的交互、样式和验收标准。

## 目标

1. 保持后端 API 与 DTO 语义不变，仅做前端体验优化。
2. 使用 `shadcn-ui` 作为输入、下拉、弹窗、按钮、表格等核心交互组件规范。
3. 提升高频路径效率：就近操作、减少冗余按钮、提升信息密度与可读性。
4. 强化移动端适配与可访问性（键盘可达、焦点可见、语义反馈完整）。

## 已锁定决策（当前基线）

1. 主题与模式
   - 页面统一亮色基调。
   - 不再展示“专业模式/极简模式”切换按钮。

2. 顶部与总览
   - 首页保留两大主标签：`组合视图`、`基金平铺`。
   - “全部组合”区域顶部显示两项汇总并带标签，左右分布：
     - 左：`基金总额`
     - 右：`今日预估收益`

3. 主操作入口（同一位置）
   - 在 `组合视图`：显示 `创建组合` 按钮（弹窗创建）。
   - 在 `基金平铺`：显示 `添加基金` 按钮（弹窗添加，需选择目标组合）。
   - 组合内部基金列表：`添加基金` 按钮位于 `手动更新` 左侧（弹窗添加，目标组合固定为当前组合）。

4. 手动更新位置
   - 全局头部不再放“手动更新”。
   - 改为放在各列表卡片头部右上角，做到就近操作：
     - 全部组合列表
     - 基金平铺列表
     - 组合内部基金列表

5. 组合列表与 Tab 交互
   - 组合名称支持点击进入组合。
   - 组合名称编辑采用行内编辑（Enter 保存、Esc 取消、blur 自动保存）。
   - 顶部组合 Tab 删除标识为右上角徽标：桌面 hover/focus 显示，移动端常显。

6. 比例达成模块（RATIO）
   - “比例达成 + 今日预估”合并为一个模块。
   - 卡片网格：移动端单列，宽屏自适应多列（最小宽度约 240px）。
   - 基金名称仅占一行，超出隐藏（省略号）。
   - 当日涨幅统一放在名称下一行展示。
   - 当日涨幅金额显示规则：
     - 不显示人民币符号。
     - 涨跌显式带符号（如 `+1000.00`、`-300.00`）。
     - 与百分比紧凑展示（如 `+1000.00(+1.23%)`）。
   - 比例条语义：计划比例作为整条基准，实际比例按相对计划比例叠加显示；超配显示具体 `+X.XX%`。

7. 组合内基金列表
   - 移除上下移动列、编辑列、更新按钮（保留 DnD）。
   - 金额与计划比例改为字段级行内编辑（Enter/Esc/blur 一致）。
   - 编辑态与展示态高度一致，避免行高跳变。

8. 反馈与状态
   - 操作反馈统一使用全局居中 Toast（`top-center`）。
   - 页面内联成功/失败提示移除。
   - 状态区仅保留“最近手动更新”。

## 范围

### In Scope

1. 首页（组合视图 / 基金平铺）所有已锁定交互与样式。
2. 组合详情中的基金列表、比例达成模块、添加基金弹窗。
3. shadcn 组件替换与样式统一（输入、选择器、按钮、弹窗、表格）。

### Out of Scope

1. 后端 API、DTO、业务校验规则变更。
2. 小程序同步改造。
3. 账号级偏好同步。

## 技术与实现约束

1. 后端 API 与 `@digmo/shared` DTO：无改动。
2. 组件库：`shadcn-ui` + `radix-ui` + `lucide-react` + `sonner`。
3. 表单：`react-hook-form + zod`。
4. 交互可访问性：
   - icon-only 按钮必须有 `aria-label`。
   - 焦点可见，Tab 顺序与视觉顺序一致。
   - 异步提交按钮 loading/disabled 防重复提交。

## 验收标准

1. 首页不再显示模式切换按钮，页面保持亮色基调。
2. “全部组合”顶部展示带标签汇总（基金总额、今日预估收益）且左右分布。
3. 组合视图通过弹窗创建组合；平铺视图通过同位置按钮弹窗添加基金。
4. 组合内部 `添加基金` 位于 `手动更新` 左侧并可正常提交。
5. 手动更新按钮仅出现在各列表卡片头部，触发同一刷新流程。
6. 比例达成模块中：
   - 名称单行省略。
   - 当日涨幅在名称下一行。
   - 金额无人民币符号，亏损为负号，金额与百分比紧凑。
7. 基金持仓字段行内编辑时行高不跳变（桌面/移动端均成立）。
8. 质量门禁：
   - `pnpm --filter @digmo/web typecheck` 通过。
   - `pnpm --filter @digmo/web build` 通过。

## 风险与缓解

1. 连续样式迭代导致规范漂移。
   - 缓解：所有新增调整先更新本 PRD，再实施代码。
2. 行内编辑与拖拽并存增加交互复杂度。
   - 缓解：固定行高、统一键盘规则、保持操作区清晰分离。
3. 多入口触发同一动作（刷新/新增）易产生状态不一致。
   - 缓解：在页面层统一 action 回调，组件仅透传事件。
